## Шинэ schema migration

`202611060004_leave_workflow` migration нь Leave-ийн төрөл/хяналтын төлөв, шийдвэрлэсэн ажилтан/огноо болон Doctor/Service-ийн `sortOrder` нэмнэ. Өмнөх бүх чөлөө `APPROVED`, өмнөх эрэмбэ `0` болж, хуучин хаалтууд хэвээр үлдэнэ.

Шинэ кодыг ажиллуулахын өмнө өөрийн deployment орчинд `bun run db:migrate` ажиллуулна. Энэ өөрчлөлтөөр бодит DB-д migration эсвэл seed ажиллуулаагүй.

## Экспортын утга

JSON нь өвчтөн, эмч, үйлчилгээ, захиалга, эмчилгээ, төлбөр, зардал, бараа/хөдөлгөөн, баримт, тэмдэглэл, шилжүүлэг, хуваарь, чөлөө, сувилагчийн ээлж, audit болон зөвшөөрөгдсөн тохиргоог агуулна. Password hash, session, password-reset token, rate-limit key, Telegram token/Chat ID болон webhook нууц орохгүй. Энэ нь бүрэн DB restore backup биш; бүрэн сэргээхэд provider backup ашиглана.

## Шалгалт

- `node --import tsx --test tests/*.test.ts`: өмнөх болон ажлын цагийн boundary шалгалтууд.
- `bun run test:workflows`: зөвхөн in-memory PGlite DB-д бүх migration, хуучин чөлөөний default, transaction rollback, хүсэлтийн шийдвэр, ownership, override, үйлчилгээний eligibility, нууц талбаргүй экспорт, бүртгэлийн бодлого, endpoint эрх болон mocked Telegram сануулгын throttle шалгана.
- Туршилт бодит DB болон Telegram-тай холбогдохгүй. PGlite нь single-connection тул native PostgreSQL concurrency, бодит Telegram хүргэлт болон production migration rehearsal-ийг орлохгүй.
