# BB Dental ERP

BB Dental эмнэлгийн нэг салбарын дотоод ERP болон үйлчлүүлэгчийн цаг захиалгын веб. Next.js 16.4, React 19, Prisma 7, Supabase PostgreSQL.

## Эхлүүлэх

1. `bun install`
2. `.env.example`-ийн утгуудыг `.env`-д тохируулна. Одоо байгаа `.env`-ийг дарж хуулж болохгүй.
3. Supabase **Connect** цэсээс runtime холболтыг `DATABASE_URL`, migration-д direct эсвэл session pooler холболтыг `DIRECT_URL`-д оруулна. Нууц үгийн тусгай тэмдэгтүүдийг URL encode хийнэ. Runtime-д PostgreSQL 5432 session эсвэл 6543 transaction pooler ашиглаж болно. Prisma-ийн DB хэрэглэгчийг зөвхөн серверт ашиглана.
4. `bun run db:migrate`
5. `/register` дээр хамгийн эхний ажилтны бүртгэл үүсгэнэ. Системийн хамгийн эхний бүртгэл автоматаар идэвхтэй `ADMIN` болно. Эсвэл `BOOTSTRAP_ADMIN_PHONE`, `BOOTSTRAP_ADMIN_PASSWORD` (8+ тэмдэгт), `BOOTSTRAP_ADMIN_NAME`, сонголтоор `BOOTSTRAP_ADMIN_EMAIL` утгуудыг тохируулж `bun run db:seed` ажиллуулж болно. Seed өмнөх админы нууц үгийг өөрчлөхгүй.
6. `bun run dev` → http://localhost:3000. Ажилтан `/login`-оор нэвтэрнэ. Дотоод ажлын орчин `/erp`.

Production: `APP_URL=https://...` тохируулна → `bun run db:migrate` → `bun run build` → `bun run start`. HTTPS шаардлагатай; production session cookie нь Secure. `public/fonts/NotoSans-Regular.ttf` файлыг deployment-д хамт оруулна (Next tracing тохиргоотой).

Supabase холболтгүй үед үндсэн нүүр хуудас, нэвтрэх форм харагдана. Өгөгдөл шаарддаг API нь тохиргоо хийгдээгүйг 503 төлөвөөр мэдэгдэнэ. Зохиомол эсвэл localStorage-д хадгалсан өгөгдөлд автоматаар шилжихгүй.

Ресепшн нь нэг эмнэлгийн нийт ажиллагааны захиалга, өвчтөний бүртгэлийг удирдана. Эмчийн өвчтөний карт, PDF, эмчилгээний түүх нь тухайн эмчид хамаарах үзлэг/эмчилгээг гаргана. Эмч хооронд карт шилжүүлсэн бол хүлээн авсан эмчид өвчтөний өмнөх клиникийн түүх нээгдэнэ. Эмчийн хариунд кассын төлбөрүүд орохгүй. Сервер route бүр дээр эрхийг дахин шалгана; UI нуух нь эрхийн хамгаалалтыг орлохгүй.

Админ ажилтан нэмэхэд `DOCTOR` дансны эмчийн profile автоматаар үүснэ. Ажилтны дансыг идэвхгүй болгох/нууц үг солиход өмнөх session-ууд хүчингүй болно. Эмчийн profile-ийн идэвхтэй төлөв нь нийтийн каталог, захиалгад харагдах эсэхийг тусад нь удирдана.

## Ажлын урсгал

- Админ үйлчилгээ, үнэ, ангилал болон эмчийн хуваарийг оруулна. Каталог нүүр хуудсанд автоматаар гарна.
- Өвчтөн үйлчилгээ → эмч/өдөр/сул цаг → нэр/утас гэсэн 3 алхмаар нэвтрэхгүй захиална. Эхний төлөв `PENDING`.
- Ресепшн бүртгэлтэй өвчтөн сонгох эсвэл нэр/утсаар шинээр бүртгэн гараар боломжит цаг сонгоно. Эхний төлөв `CONFIRMED`. Захиалгын хүснэгтээс эмчилгээ, төлбөр, давтан цаг болон цаг шилжүүлэх үйлдлүүдтэй.
- Календарь өдөр, долоо хоног, сараар харагдана. 15 минутын алхамтай цагийн сонголт нь үйлчилгээний хугацаа, хуваарь, чөлөө, өмнөх захиалгыг тооцно. Хугацаа нь Улаанбаатарын цагаар.
- Захиалга үүсгэх/шилжүүлэх болон хуваарь/чөлөөг өөрчлөхөд PostgreSQL transaction + эмчийн advisory lock ашиглана. Давхар захиалга болон захиалгатай зөрчилдөх хуваарийг сервер хориглоно.
- Өвчтөний картаас өмнөх үйлчилгээ, эмчийг ашиглан **давтан цаг** шууд үүсгэнэ. Өмнөх захиалгатай `repeatOfId` холбоо хадгалагдана.
- Байнгын 32, сүүн 20 шүдийг FDI дугаараар сонгон онош, хийсэн эмчилгээ, тэмдэглэл, дүнг бүртгэнэ. Схемийн өнгө нь эмчилгээний бүртгэлтэй шүдийг илэрхийлнэ; автомат онош биш.
- Касс нь өвчтөн, дүн, төлбөрийн хэлбэр (бэлэн/карт/шилжүүлэг/QPay) болон огноог **дотоод системд** хадгална. Банк, QPay руу төлбөрийн хүсэлт илгээхгүй, eBarimt үүсгэхгүй. Давхар submit-ийг unique idempotency key-ээр хориглоно. Зөвхөн админ шалтгаантайгаар хүчингүй болгоно; мөрийг арилгахгүй.
- Барааны хөдөлгөөн нь нэмэх/хасах signed quantity ашиглана. Үлдэгдэл сөрөг болгох үйлдэл transaction дотор буцна. Бараа бүр нийлүүлэгч, код, нэгж, доод нөөцтэй.
- Баримтын агуулга, зөвшөөрөл өгсөн нэрийг хадгалж PDF гаргана. Нэр оруулах нь цахим гарын үсэг биш; PDF дээр гарын үсэг зурах зайтай.
- Өвчтөний мэдээллийн PDF карт Монгол үсгийг дэмжих Noto Sans фонтыг embed хийнэ. PDF-ийг нээгээд хэвлэх эсвэл хадгалах боломжтой.

## Тайлан ба dashboard

Бүх хугацаа, сар, жил, өнөөдрөөр шүүнэ. Орлого нь хүчингүй болгоогүй **бүртгэсэн төлбөр**, зардал нь **зардлын бүртгэл**, цэвэр дүн нь тэдгээрийн зөрүү. Эмчилгээний дүн/төлбөрийн зөрүү нь эмчилгээ ба төлбөр бүртгэсэн огнооноос хамаарна; нягтлан бодох бүртгэлийн бүрэн баланс биш.

Стандарт Excel: нэгдсэн дүн, өвчтөн/үйлчилгээ/эмчтэй төлбөрийн журнал, зардал, эмчийн ачаалал гэсэн sheet-үүд. PDF: нэгдсэн дүн, төлбөрийн хэлбэр, эмчийн ачаалал, төлбөрийн журнал. Хэрэглэгчийн тусгай маягтыг дараа өгнө; одоогийн стандарт экспорт нь тэр маягтыг орлоогүй.

Тайлангийн өгөгдөл `lib/reports.ts`, экспорт `app/api/export/[kind]/route.ts`-д төвлөрсөн. Дурын өгөгдлийн сан руу migration автоматаар ажиллахгүй.

## Өвчтөн утсаар захиалгаа харах

Хэрэглэгчийн хүссэнээр SMS кодгүй: утсаа оруулах → “энэ дугаар зөв үү?” → зөвхөн захиалсан үйлчилгээ, эмч, өдөр/цаг, төлөвийг харуулна. Энэ нь дугаарын эзэмшлийг батлахгүй; дугаарыг мэдэх хүн ижил мэдээллийг харж чадна. Нэр, өвчтөний карт, онош, тэмдэглэл, төлбөрийг энэ API-аар буцаахгүй. Утас URL/query-д орохгүй, POST body ашиглана; rate limit-тэй. Жинхэнэ эзэмшлийн баталгаажуулалт хэрэгтэй бол дараа SMS OTP нийлүүлэгч холбоно.

## Telegram

`TELEGRAM_BOT_TOKEN` тохируулж, админ эмчийн profile-д тоон `telegramChatId` хадгална. Эмч bot дээр `/start` дарсан байх ёстой. Бүртгэл дэх Telegram ID нь зөвшөөрөгдсөн эмчийн profile-тай автоматаар холбогдоно. Эмчийн profile дээрээс туршилтын мэдэгдэл илгээж болно. Шинэ/шилжүүлсэн цаг болон өвчтөн шилжүүлгийн мэдэгдэл явна; онош, өвчтөний нэр/утас дамжуулахгүй. Token байхгүй үед мэдэгдэл алгасна. Telegram доголдвол амжилттай захиалгыг буцаахгүй; тусгай retry queue одоогоор байхгүй.

## Шалгалт

```sh
bun run test       # огноо, давхцал, төлбөр, утас, FDI validation
bun run build      # Prisma generate, production compile, TypeScript
```

Бүрэн integration/browser тест нь зөвхөн localhost дээр нэр нь `_test`-ээр төгссөн **тусгаарласан, ажилтан бүртгэлгүй шинэ PostgreSQL** сан дээр ажиллана. Эхний бүртгэлийн тест нь User хүснэгт хоосон байхыг шаарддаг. Жинхэнэ Supabase өгөгдөл ашиглахгүй.

```sh
# Тестийн санг өөрөө үүсгэн, URL-ийг зөвхөн тухайн process-д өгнө.
export ERP_TEST_DATABASE_URL="postgresql://USER:PASSWORD@localhost:5432/bb_erp_test"
DATABASE_URL="$ERP_TEST_DATABASE_URL" DIRECT_URL="$ERP_TEST_DATABASE_URL" bun run db:migrate
bun run build
bun run test:e2e
```

`bunx playwright install chromium` шаардлагатай байж болно. Browser тест нь нэвтрэлт, эрх, өөр эмчийн өвчтөнд хандах хориг, давхар booking, кассын дүн/давхардал, барааны үлдэгдэл, PDF/Excel болон responsive дэлгэцийг шалгана. Тест өгөгдлүүд тухайн тусгаарласан санд үүснэ.

## Эх сурвалж ба одоогийн хязгаар

[DentHub-ийн нийтэд харагдах танилцуулгын](https://www.denthub.mn/) 8 үндсэн ажлын урсгалыг BB Dental-ийн 3 эрхэд тохируулж тусад нь хэрэгжүүлсэн. DentHub-ийн хувийн системийн код, данс эсвэл өгөгдөлтэй интеграци хийгдээгүй. Одоогоор олон салбар, SMS OTP/2FA, Excel импорт, цахим гарын үсэг болон банкны төлбөрийн холболт ороогүй. Telegram-ээр нууц үг сэргээхэд bot token, хувийн Chat ID, APP_URL; имэйл сонгосон үед SMTP тохируулна.

Supabase-ийн live URL, анхны админы мэдээлэл болон тусгай тайлангийн маягтыг хэрэглэгч дараа тохируулна/өгнө. Production Supabase холболт болон жинхэнэ Telegram хүргэлтийг тэдгээр тохиргоогүйгээр шалгах боломжгүй.

Шалгасан холболтын заавар: [Supabase Prisma](https://supabase.com/docs/guides/database/prisma), [Prisma 7 driver adapter](https://www.prisma.io/docs/orm/v7/prisma-client/setup-and-configuration/databases-connections/connection-pool). Фонтын лиценз: `public/fonts/OFL.txt`.


## Бүртгэл, админы хяналт

`/register`: нэр, имэйл, утас, сонголтоор тоон Telegram Chat ID, хүсэж буй эрх (эмч/ресепшн), нууц үг болон давтан нууц үг. Нууц үг хамгийн багадаа 8 тэмдэгт, bcrypt-ийн хязгаараар 72 байтаас хэтрэхгүй. Имэйл lowercase-аар, утас улсын кодгүй 8 оронгоор хадгалагдана.

Хамгийн эхний бүртгэл PostgreSQL advisory lock дотор тоологдож автоматаар `ADMIN / APPROVED / active` болно. Зэрэг ирсэн бусад бүртгэл `PENDING / inactive` байна. Одоо байгаа хэрэглэгчид шинэ migration-аар `APPROVED` төлөвтэй үлдэнэ. Дараагийн бүртгэлийг админ **Ажилтан, эрх → Хянах** хэсгээс эрхийг нь сонгон зөвшөөрөх эсвэл татгалзана. Хүлээгдэж буй эмчийн profile нь нийтийн каталогт харагдахгүй, нэвтрэх боломжгүй. Админ хяналтаас гадуур pending дансыг active болгож болохгүй.

## Нууц үг сэргээх

`/forgot-password` нь анхдагчаар Telegram сонголттой. Ажилтан бүртгэлтэй утсаа оруулахад холбоос нь зөвхөн User дээр хадгалсан хувийн Telegram Chat ID руу очно. Chat ID эсвэл холбоосын хүлээн авагчийг энэ form/API-аас солих боломжгүй. Идэвхгүй, зөвшөөрөөгүй эсвэл Telegram ID-гүй дансны тухай мэдээллийг нийтийн хариунд илчлэхгүй. Имэйл сонголт мөн ашиглаж болно. `SMTP_HOST`, `SMTP_PORT`, `SMTP_USER`, `SMTP_PASSWORD`, `SMTP_FROM` болон зөв `APP_URL`-ийг `.env`-д тохируулна. 465 нь шууд TLS, 587 нь STARTTLS. Нууц үг сэргээх имэйл нь 30 минут хүчинтэй, нэг удаагийн холбоостой. Token зөвхөн SHA-256 хэштэйгээр санд хадгалагдана. Амжилттай шинэчлэхэд өмнөх бүх session болон бусад сэргээх холбоос хүчингүй болно. SMTP тохиргоогүй үед алдааг тодорхой харуулна; сэргээх token-ийг UI/API/log-д буцаахгүй. Имэйл олдсон эсэхийг амжилттай хүсэлтийн хариунд ялгахгүй.

Нэвтрэх, бүртгүүлэх, сэргээх болон админы нууц үгийн формуудад харах/нуух нүдтэй.

## Өвчтөн шилжүүлэх, дотоод тэмдэглэл

Өвчтөний карт дээр **Эмчид шилжүүлэх**-ийг сонгон хүлээн авах эмч, шалтгааныг оруулна. Эмч өөрт нь хамаарах өвчтөнийг л шилжүүлнэ; админ хяналтын эрхтэй. Хүлээн авах эмч идэвхтэй, зөвшөөрөгдсөн данстай байна. Шилжүүлэг нь картын клиникийн түүхийн хандалтыг нээж, хэнээс хэнд, хэн бүртгэсэн, шалтгаан, огноог хадгална. Өмнөх үзлэгийн эмчийн түүхэн холбоос хадгалагдана; цаг товлолыг өөрчлөх бол цаг шилжүүлэх үйлдлийг ашиглана. Өмнөх эмч өөрийн эмчилгээний түүхийг харах боломжтой хэвээр.

Дотоод тэмдэглэлийг админ/ресепшн болон картын хандалттай эмч нэмнэ. Тэмдэглэл нь өвчтөний карт дээр бичсэн хүний нэр, эрх, огноотой хадгалагдана; нийтийн утсаар захиалга харах API-д орохгүй.

Шинэ migration: `202611060001_registration_patient_handover`. Холбогдсон орчинд `bun run db:migrate` ажиллуулна. Хувийн production Supabase санд migration автоматаар хэрэгжүүлээгүй.


## Telegram-ээр нууц үг сэргээх, админаас илгээх

- `TELEGRAM_BOT_TOKEN`, `APP_URL`-ийг тохируулна. Production холбоос нь HTTPS байна. Ажилтан эмнэлгийн bot дээр `/start` дарсан, User бүртгэлдээ өөрийн **эерэг тоон хувийн Chat ID**-тай байна. Бүлгийн сөрөг Chat ID руу сэргээх холбоос илгээхгүй.
- Ажилтан `/forgot-password` → Telegram → бүртгэлтэй утас → холбоос авах урсгалаар шинэ нууц үг үүсгэнэ. Telegram-гүй ажилтан имэйл сонголтыг ашиглах эсвэл админд хандана.
- Админ **Ажилтан, эрх** хүснэгтийн түлхүүр дүрстэй **Telegram руу сэргээх холбоос илгээх** товчоор идэвхтэй, зөвшөөрөгдсөн ажилтны хадгалсан Telegram руу илгээнэ. Chat ID-гүй үед товч идэвхгүй. Сервер талд ADMIN эрх, дансны идэвхтэй/зөвшөөрөгдсөн төлөв, rate limit-ийг шалгана.
- Token нь 30 минут, нэг удаагийн хэрэглээтэй; санд зөвхөн хэш хадгална. Админ болон API хариунд token/холбоосыг буцаахгүй. Хүргэлт амжилтгүй бол тухайн token хүчингүй болно. Амжилттай шинэчилсний дараа хуучин бүх session хүчингүй болно.
- Админы илгээсэн үйлдэл `ADMIN_PASSWORD_RESET_SENT` audit мөртэй. Ажилтны хүсэлт `PASSWORD_RESET_REQUESTED` мөртэй. Дараагийн шинэ холбоос өмнөх ашиглаагүй холбоосуудыг хүчингүй болгоно.
- Энэ өөрчлөлтөд нэмэлт database migration шаардлагагүй. Өмнөх `PasswordReset` хүснэгтийг ашиглана.

Telegram интеграцийн тест нь `e2e/telegram-preload.mjs`-ээр зөвхөн localhost mock руу чиглүүлдэг; тестүүд бодит bot/хаяг руу холбоос илгээхгүй.


## Cloudinary зураг ба PDF загвар

Админ **Эмч нар → нэмэх/засах**, **Үйлчилгээ → нэмэх/засах** хэсгээс файл сонгон зураг оруулна. **Тохиргоо → Эмнэлгийн лого · Веб ба PDF** хэсэгт лого оруулбал нүүр хуудасны header, hero, footer болон бүх PDF-д хэрэглэгдэнэ. Зургийн URL-ийг гараар хуулж тавих шаардлагагүй.

`.env`-д `CLOUDINARY_URL=cloudinary://API_KEY:API_SECRET@CLOUD_NAME` эсвэл `CLOUDINARY_CLOUD_NAME`, `CLOUDINARY_API_KEY`, `CLOUDINARY_API_SECRET` гэсэн гурван утгыг тохируулна. URL байгаа бол түүнийг давуу ашиглана. API secret нь зөвхөн серверт ашиглагдана; browser/API хариунд буцаахгүй. Unsigned upload preset шаардлагагүй.

Upload нь ADMIN эрх, same-origin, rate limit шалгалттай. Файлын агуулгаас JPG/PNG/WEBP эсэхийг шалгаж, 5 MB хүртэл хүлээн авна. Зургууд Cloudinary-ийн `bb-dental/doctors`, `bb-dental/services`, `bb-dental/logo` хавтаст хадгалагдана. Эмч/үйлчилгээний зураг хамгийн ихдээ 1800×1800, лого 512×512 хэмжээнд багтана. Лого PNG хэлбэрээр хувиргагдаж PDF-д embed хийх боломжтой байна.

Зургийн файлууд нь нийтийн танилцуулгын эмч/үйлчилгээ/логоны зориулалттай. Өвчтөний эмнэлгийн зураг, хувийн баримтыг энэ нийтийн Cloudinary image upload-аар оруулах урсгал хийгдээгүй. Зургийг формаас арилгахад бүртгэлийн холбоос цэвэрлэгдэнэ; өмнө байршуулсан Cloudinary asset автоматаар устахгүй.

Шинэ migration: `202611060002_service_image`. Өөрийн орчинд `bun run db:migrate` ажиллуулна. Production Supabase-д энэ migration-ийг автоматаар хэрэгжүүлээгүй.

PDF загвар `lib/pdf.ts`-д төвлөрсөн: A4 цагаан суурь, ногоон брэндийн өнгө, эмнэлгийн лого/нэр/холбоо барих мэдээлэл, Монгол үсэгтэй embedded фонт, мэдээллийн карт, хүснэгт, урт мөрийн үргэлжлэл, хуудас бүрийн header/footer, хэвлэсэн Улаанбаатарын огноо, хуудасны дугаар. Өвчтөний карт, зөвшөөрөл/баримт, санхүүгийн PDF тайлан бүгд энэ загвартай. Баримтад нэр, гарын үсэг, огнооны зайтай.

PDF-ийн remote logo-г зөвхөн тохируулсан өөрийн Cloudinary cloud-ийн image/upload URL-аас, хязгаарлагдсан хэмжээ/хугацаатай татна. Хүргэлт алдагдсан, файл буруу эсвэл лого тохируулаагүй үед төслийн BB Dental логог ашиглана. PDF үүсгэх, татах нь өмнөх staff эрхийн шалгалттай.

Тестүүд Cloudinary-г локал mock руу чиглүүлнэ; бодит Cloudinary-д asset үүсгэхгүй. Зөв signed параметр, хортой файл/хэмжээ, admin эрх, upload form, logo setting, PDF дэх image/font болон олон хуудсанд үргэлжлэх урт Монгол текстийг шалгана.

Холбогдох баримт: [Cloudinary signed upload](https://cloudinary.com/documentation/authentication_signatures), [PDFKit image embedding](https://pdfkit.org/docs/images.html).


## Ажилтны шинэ удирдлага, эрх солих

`/erp/users` нь ажилтны карт, нэр/утас/имэйлээр хайлт, эрхийн шүүлтүүр, зөвшөөрөл хүлээж буй/идэвхтэй/идэвхгүй төлөвийн таб, карт/жагсаалтын харагдацтай. Картын **Эрх солих** үйлдлээр ADMIN, DOCTOR, RECEPTION эрхийг хооронд нь солино. Шинэ эмчийн дансанд профайл үүснэ. Эмчээс өөр эрх рүү шилжихэд профайл устахгүй, идэвхгүй болно; өмнөх үзлэг, эмчилгээ, шилжүүлэг, хуваарийн холбоос хадгалагдана. Буцаад DOCTOR болоход өмнөх профайл ашиглагдана. Эрх солиход тухайн ажилтны session-ууд хүчингүй болж дахин нэвтэрнэ.

Сүүлчийн идэвхтэй, зөвшөөрөгдсөн ADMIN-ийн эрхийг хаах боломжгүй. Өөр идэвхтэй админ байгаа үед өөрийн эрхийг ч өөрчилж болно; өөрийн мэдээллийг хадгалбал дахин нэвтрэх хуудас руу шилжинэ. Эрх солих нь өмнөх захиалгыг өөр эмчид автоматаар шилжүүлэхгүй; шаардлагатай захиалгыг админ/ресепшн цаг шилжүүлэх урсгалаар удирдана.

## Telegram тохиргооны удирдлага

**Тохиргоо → Telegram**:

- Bot холболт шалгах (`getMe`), нэр/username харах, bot нээх.
- Шинэ bot token-ийг шалгаад шифрлэн хадгалах. `TELEGRAM_BOT_TOKEN` environment нь fallback; UI-д хадгалсан token байвал түүнийг хэрэглэнэ. UI/API нь хадгалсан token-ийг буцааж харуулахгүй.
- Цаг захиалга/шилжүүлсэн цаг, өвчтөн шилжүүлэг, нууц үг сэргээх гэсэн гурван үйлдлийг тус тус асаах/унтраах. Туршилтын мэдэгдэл эдгээр pause-оос үл хамаарч холболтыг шалгана.
- Webhook холбох, төлөв/хүлээгдэж буй хүсэлт/сүүлийн алдаа харах, webhook салгах. `APP_URL` нийтэд нээлттэй HTTPS байна. Хүлээгдэж буй update-уудыг устгахгүй.

Token-ийг UI-аас хадгалахад **32 байтын `SETTINGS_ENCRYPTION_KEY`** шаардлагатай. Base64 эсвэл 64 hex утга хүлээн авна. Үүсгэх жишээ:

```sh
node -e 'console.log(require("crypto").randomBytes(32).toString("base64"))'
```

Түлхүүрийг `.env`-д хадгалж нөөцөлнө. Token нь AES-256-GCM-аар шифрлэгдэнэ. Түлхүүргүй үед environment token-ийг ашиглаж болох ба UI-аас token хадгалах боломжгүй. Түлхүүр өөрчлөгдвөл өмнөх token-ийг нээх боломжгүй учир хуучин түлхүүрээ сэргээх эсвэл шинэ token хадгална. Серверийн token ашиглах товч нь DB override-ийг арилгана.

## Ажилтны Telegram-ийг автоматаар холбох

Ажилтны картын **… → Telegram холбох** үйлдэл 15 минут хүчинтэй, нэг удаагийн `https://t.me/BOT?start=...` холбоос үүсгэнэ. Ажилтан өөрийн хувийн Telegram-аас холбоосыг нээгээд Start дарна. Secret header-тай `/api/telegram/webhook` нь холбоосыг шалгаж User болон холбоотой Doctor-ийн Chat ID-г шинэчилнэ. Link нь raw token биш SHA-256 key-ээр хадгалагдана. Хугацаа дууссан, ашигласан, буруу secret header-тай хүсэлтээр холбохгүй. Group chat-ийг холбохгүй.

Энэ автомат холболтод webhook-ийг эхлээд тохируулсан байна. Localhost HTTP дээр webhook суулгахгүй; нийтэд нээлттэй HTTPS staging/production хаяг шаардлагатай. Chat ID-г админ гараар оруулах урсгал хэвээр. Картын нэмэлт цэсэнд мэдэгдэл турших болон Telegram руу нууц үг сэргээх холбоос илгээх үйлдлүүд бий.

## Footer-ийг засах

**Тохиргоо → Эмнэлэг ба footer** хэсэгт эмнэлгийн нэр, утас, имэйл, хаяг, ажиллах цаг, танилцуулга, хэсгүүдийн гарчиг, цаг захиалах товчны текст, copyright, Facebook/Instagram HTTPS холбоосуудыг засна. Footer-ийн урьдчилсан харагдацтай. Нэг хадгалалтаар мэдээлэл transaction дотор шинэчлэгдэнэ. Нийтийн API нь зөвхөн footer/эмнэлгийн allowlist-ийг буцаана; Telegram token, шифрлэгдсэн secret болон нэг удаагийн link-үүдийг гаргахгүй.

Лого болон тайлангийн гарчиг **Лого ба тайлан** таб руу шилжсэн. Энэ удаагийн өөрчлөлт нэмэлт migration шаардлагагүй; өмнөх User/Doctor/Setting хүснэгтүүдийг ашиглана.

## Боломжит цаг, Telegram товч, багийн календарь, өнгөний горим

`202611060003_booking_roster` migration нь үйлчилгээний `doctorIds` болон `NurseShift` хүснэгт нэмнэ. Өөрийн DB-д `bun run db:migrate` ажиллуулна. Хуучин үйлчилгээний эмчийн сонголт хоосон тул бүх идэвхтэй эмч авах боломжтой хэвээр. **Үйлчилгээ → засах → Үйлчилгээ авах боломжтой эмч** хэсэгт тодорхой эмчдийг сонгож хязгаарлана.

- Үйлчлүүлэгч үйлчилгээ/өдрөө сонгоход тухайн үйлчилгээг авдаг, ажлын хуваарьтай, чөлөө/захиалгатай давхцаагүй эмчид сул цаг санал болгоно. Үйлчилгээний хугацааг нийтийн каталог, захиалгын дэлгэцэд харуулахгүй. Систем хугацаагаар нь дуусах цаг, дараагийн боломжит цагийг тооцоолж, захиалах үед doctor lock дотор давхцлыг дахин шалгана. Нийтийн захиалгын лавлагаанд зөвхөн эхлэх цаг харагдана.
- Telegram шинэ болон шилжүүлсэн захиалгад эмч, өвчтөний нэр/утас, үйлчилгээ, өдөр/цагтай мэдэгдэл илгээнэ. Батлах/цуцлах inline товч нь webhook-оор ажиллана. **Тохиргоо → Telegram → Webhook холбох** товчийг дахин дарж `callback_query` update-ийг идэвхжүүлнэ. Энэ нь нийтэд нээлттэй HTTPS `APP_URL`, bot-оо Start хийсэн бүртгэлтэй эмчийн хувийн Chat ID шаарддаг. [Telegram Bot API](https://core.telegram.org/bots/api#callbackquery)-ийн callback_query, answerCallbackQuery урсгалыг ашиглана.
- Товч нь тухайн захиалгын идэвхтэй, зөвшөөрөгдсөн DOCTOR данстай эмчид үйлчилнэ. Бусдын, хуучин цаг/эмч/үйлчилгээтэй мэдэгдэл, өнгөрсөн/дууссан захиалгыг өөрчлөхгүй. Зэрэгцээ баталгаажуулалтаар нэг удаа өөрчлөгдөж audit мөр үүснэ. Telegram хүргэлт амжилтгүй болсон ч захиалга хадгалагдсан байна.
- **Ажлын хуваарь** болон **Календарь** хэсгийн багийн календараас өдөр тутмын эмч/сувилагчийн тоог харна. Өдөр → эмч дээр дарвал ажлын үлдсэн интервал, захиалга, долоо хоногийн хуваарь, чөлөө харагдана. Чөлөөний интервалуудыг ажлын цагаас хасаж харуулна. Эмч зөвхөн өөрийн хуваарь, админ/ресепшн багийн хуваарийг харна. Админ сувилагчийн нэр, өдөр, эхлэх/дуусах цагаар ээлж бүртгэх/арилгах боломжтой. Сувилагчид шинэ нэвтрэх эрх үүсгээгүй.
- Эмчилгээний формд байнгын 32, сүүн 20 шүдийг FDI зураг дээр дарж сонгоно. Сонголт нь өмнөх `Treatment.tooth` талбарт хадгалагдана.
- **Тайлан** хэсэгт үйлчилгээний шүүлтүүр болон захиалга/дууссан үзлэг/эмчилгээний тоо, эмчилгээний дүн, авсан төлбөрийн задаргаа нэмэгдсэн. Excel-д **Үйлчилгээгээр** хуудас, PDF-д үйлчилгээний хүснэгттэй. Захиалгад холбоогүй шууд төлбөрийг дур мэдэн үйлчилгээнд хуваарилахгүй. Үйлчилгээний тайланд нийтлэг зардлыг хуваарилаагүй учир тэг гэж үзүүлнэ; энэ нь үйлчилгээний бодит ашгийн тооцоо биш.
- Бүх эрхийн нүүр хэсэгт тухайн ажилд тохирсон товчлолуудтай. Дэлгэцийн баруун доод буланд гэрэлтэй/бараан/төхөөрөмжийн горим сонгоно. Сонголт browser-ийн localStorage-д хадгалагдаж дахин нээхэд хэвээр байна.

Эдгээр Telegram үйлдлийг бодит bot руу мессеж илгээхгүй localhost mock-той E2E шалгалтаар шалгана.

## Өөрийн профайл, browser icon, ачааллын харагдац

Админ, эмч **Миний профайл** цэс эсвэл дээрх нэрийн дүрсээс `/erp/profile`-ийг нээж өөрийн нэр, утас, имэйл, Telegram Chat ID-г шинэчилнэ. Эмч мэргэжил, танилцуулга, Cloudinary профайлын зургаа өөрөө засна; энэ мэдээлэл нийтийн эмчийн танилцуулгад шинэчлэгдэнэ. `/api/profile` нь session-ийн эзний мэдээллийг л өөрчилнө; хэрэглэгчийн ID, эрх, идэвхтэй төлөв, зөвшөөрлийн төлөв зэрэг нэмэлт талбар хүлээн авахгүй. Эмч зөвхөн `doctors` зориулалтаар зураг upload хийх боломжтой. Үйлчилгээ болон лого upload нь админд хэвээр.

`app/favicon.ico`, `app/icon.png`, `app/apple-icon.png` нь одоогийн BB Dental логоны browser tab, өндөр нягтрал болон Apple shortcut хувилбарууд. Browser хуучин icon-ийг cache-ласан бол хуудсыг дахин ачаалж шалгана.

`BrandLoader` нь цагаан BB Dental үсгийг зөөлөн хөдөлгөж харуулна. Route болон эрх шалгах үеийн бүтэн дэлгэц, ERP-ийн мэдээлэл ачаалах хэсэгт хэрэглэнэ. Хиймэл саатал, дуусах хувийн тоолуур нэмэхгүй; өгөгдөл ирэхэд шууд агуулга гарна. Reduced motion тохиргоотой үед хөдөлгөөн унтарна. Энэ өөрчлөлт нэмэлт migration шаардахгүй.
